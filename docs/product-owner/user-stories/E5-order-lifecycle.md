# E5 订单生命周期与支付边界

← [用户故事地图](../User-Story-Map.md)

## 背景

结账已能创建订单并发起支付，但履约状态可跳步、取消规则前后端不一致，且支付结果与履约进度混在同一套状态里，客服与管理难以区分「已收款未发货」与「未付款」。

---

## US-11 订单仅允许合法状态迁移

**As a** 管理员  
**I want** 订单状态只能按约定路径前进或进入取消  
**So that** 履约进度不可跳步或回退到非法状态

### 验收标准

1. **Scenario** 拒绝跳步  
   **GIVEN** 订单状态为 `pending`  
   **WHEN** 尝试直接改为 `shipped` 或 `delivered`  
   **THEN** 变更被拒绝且订单状态不变

2. **Scenario** 合法前进  
   **GIVEN** 订单状态为 `processing`  
   **WHEN** 更新为下一履约状态 `shipped`  
   **THEN** 订单状态变为 `shipped`

3. **Scenario** 终态不可再履约前进  
   **GIVEN** 订单状态为 `delivered` 或 `cancelled`  
   **WHEN** 尝试改为其他履约状态  
   **THEN** 变更被拒绝

## US-12 顾客按规则取消订单

**As a** 顾客  
**I want** 在约定窗口内取消未完成履约的订单  
**So that** 取消策略前后端一致，已发货订单不可取消

### 验收标准

1. **Scenario** 待处理可取消  
   **GIVEN** 订单状态为 `pending` 且属于当前顾客  
   **WHEN** 顾客请求取消  
   **THEN** 订单变为 `cancelled`

2. **Scenario** 处理中可取消（与约定一致）  
   **GIVEN** 产品约定允许在 `processing` 取消  
   **WHEN** 顾客或管理端按同一规则取消  
   **THEN** 两端接受或拒绝结果一致

3. **Scenario** 已发货不可取消  
   **GIVEN** 订单状态为 `shipped` 或 `delivered`  
   **WHEN** 请求取消  
   **THEN** 请求被拒绝且状态不变

## US-13 支付结果与履约状态可区分

**As a** 管理员或客服  
**I want** 查看订单时能区分是否已收款与当前履约进度  
**So that** 已收款未发货与未付款不会被同一状态混淆

### 验收标准

1. **Scenario** 支付成功后仍可待履约  
   **GIVEN** 顾客已完成支付  
   **WHEN** 查看该订单  
   **THEN** 可见支付已成功的标识或字段  
   **AND** 履约状态仍可为待处理或处理中

2. **Scenario** 未付款与已付款列表可区分  
   **GIVEN** 同时存在未付款与已付款订单  
   **WHEN** 在管理端按支付结果筛选或查看详情  
   **THEN** 两类订单可被区分，不单靠履约状态推断
